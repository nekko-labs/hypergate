# CLI installs carry on into sign-in

Installing a CLI that needs an account no longer stops at the install. Hypergate now walks you into the account setup too.

### Features

- **CLI installs continue through account setup.** When an in-app install finishes and the curated CLI still needs an account, Hypergate starts the vendor's sign-in or setup command itself, as long as that command can complete with a browser handoff and no terminal (`az login`, `flyctl auth login`, `wrangler login`). Commands that need an interactive terminal (`gh auth login`, `aws configure`, `gcloud auth login`, and similar) become an explicit next step: the exact command, why Hypergate cannot run it for you, and **Copy**. Installed rows keep this setup step visible instead of hiding it under **Manage**, and a successful setup says the CLI is ready to use.
- **Agent-requested installs chain through setup too.** Approving an install an agent asked for returns the tool's setup hint, and the app starts the follow-up sign-in job on its own.

### Changes

- **Nekko Agent naming.** References to the sibling product now use its current name, Nekko Agent (formerly Kotrain and Agent Nekko), across the app, CLI output, the site and the docs. Its registry entry and command are now `nekko-agent`.
