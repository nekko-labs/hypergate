# Updating works when the daemon outlives the tray

### Bug fixes

- **"Hypergate is still running" no longer blocks every update.** Applying an update asked the Hypergate tray to quit and assumed that took the background daemon down with it. It often does not: the daemon is deliberately detached so your MCP servers keep running when you close the window, which means a daemon started before the current tray outlives it and keeps holding the API port. The updater waited 30 seconds for that port to go quiet, never saw it, and gave up with the app left untouched — reporting "Hypergate is still running", which was true and impossible to act on. It now confirms the daemon actually stopped and stops it itself when it did not.

### Before updating

- **This fix ships *in* the new version, so it cannot repair the update that is failing now.** If updating already fails this way, quit Hypergate completely and run `hypergate update --apply` from a terminal once. With no tray to ask, the updater stops the daemon directly, which is the path that already worked. Every update after that is fixed.
