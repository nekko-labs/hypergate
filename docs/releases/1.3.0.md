# Kotrain connects in one click, and releases cut themselves

Two releases' worth of work goes out here: v1.1.0 and v1.2.0 were bumped but never tagged, so their changes ship under this version. That gap is also what this release fixes, a version bump merged to `main` now cuts the release itself.

### Features

- **Kotrain connects in one click, from either side.** Kotrain used to be a *config* target: copy a snippet, find `~/.kotrain/settings.json`, paste it in. That was worse than tedious, it was wrong, because Kotrain holds its settings in memory while it runs and writes the whole file back on its next change, so a config written underneath a running app is simply overwritten. There is no file to write and no CLI to run, so the app does it. A fourth connect method, `deeplink`, hands the job to a client that registered a URL scheme: `kotrain://hypergate/connect?port=N`, where the port is the entire payload. A token in a URL would be a credential handed through the OS's link handler on the word of whoever opened it, so the client instead reads its own back over loopback and asks its user first. The panel is now one button, with the `settings.json` snippet still underneath for a machine that doesn't have Kotrain yet. Connecting this way also fixes what the agent list showed: Kotrain sat at "Offline, never used" because it had never used its scoped token, and now shows Active with its own permissions and usage history.

### Bug fixes

- **A failing remote server shows one readable line, not a wall of HTML.** Hosted endpoints answer their failures with a web page, and Hypergate used to display that entire page as the server's error, with the status code lost somewhere inside it. A server that returns HTTP 500 now reads: "HTTP 500: the endpoint answered with an HTML error page instead of MCP. The host is failing upstream, so there is nothing to fix in this config." The advice fits the status, so a 401 asks you to sign in again and a bad URL says to check it. The full response is still in the server's log panel if you want it.
- **A remote server that is down no longer asks you to sign in.** Whether a server needed authorizing was decided by looking for "401" anywhere in the error text, and an error page's own markup can contain that string for unrelated reasons. Hypergate now reads the actual HTTP status, so only a real 401 sends you to sign in.

### Under the hood

- **Merging a version bump ships the release.** Releases were cut by hand-tagging, and since every PR bumps the version, bumps outran tags, v1.1.0 and v1.2.0 both went unreleased. `version-release.yml` now watches pushes to `main` that touch `package.json`, and when that version has no tag yet it tags it and builds the installers. It refuses to tag when the seven version files disagree or when the release's notes file is missing, so a partial bump fails while there is still nothing tagged. Hand-tagging still works, as the fallback.
