# A CLI an agent can drive, and an install you can trust

A production-readiness release: everything the manager can do is now reachable from the terminal, and the parts that guard your machine got closed properly.

### Features

- **Every command speaks JSON.** `--json` works on any command, so an agent reads one object instead of scraping aligned columns.
- **`hypergate doctor`.** One command says whether this install is healthy: daemon, token storage, keychain, agents and their scopes, servers, updates and login item, with a non-zero exit when something needs attention.
- **Connected agents from the terminal.** `hypergate agent` lists, creates, scopes, renames and removes the per-agent tokens that used to be UI-only, and `hypergate targets` / `hypergate connect` wire a harness up without opening the manager.
- **A leaked agent token can be replaced.** `hypergate agent rotate` issues a new one and keeps the agent's name and its server allow-list, instead of deleting and rebuilding it.
- **The tool catalog, with a one-command install.** `hypergate cli` says which tools this machine has, searches for more, and installs a curated one for you — only when you ask with `--run`, and only when the vendor's instruction is a plain command rather than a page to read.
- **Your own call history.** `hypergate usage` prints what the Analytics tab shows.

### Bug fixes

- **A web page you visit can no longer change your Hypergate.** Any site could fire a request at the local manager and have it act on your behalf; now every change requires the manager's own origin, and a site that points its own domain at your machine is turned away.
- **Updates taken from a release are checked.** Downloads that came from a release's attached files were only checked for length; they are now verified against the release's published checksums, like the ones from npm, and refused outright when there is nothing to verify against.
- **Upgrading on Windows no longer kills the wrong thing.** The installer force-stopped every process named `hypergate.exe` on the machine, and never stopped the background service at all, so an upgrade over a running Hypergate could leave the old service in place. It now stops only the processes belonging to the copy being replaced, and fails loudly rather than quietly keeping a stale binary.
- **Windows no longer flattens variables out of your PATH.** Adding Hypergate to PATH rewrote every entry with variables such as `%USERPROFILE%` expanded to whatever they meant at that moment.
- **The Linux app entry shows up immediately.** The menu entry and icon appeared only after the next login on many desktops.
- **macOS can be uninstalled.** The `.pkg` had no way out; it now ships `uninstall.sh` inside the app, which removes the app, the commands and the receipt and leaves `~/.hypergate` alone.
- **The Mac app installs beside the `hypergate` command.** On a case-insensitive disk the app's launcher and the CLI wanted the same name, which could fail the install.
- **Log redaction no longer splits characters.** Hiding credential-shaped text from the log could cut a multi-byte character in half.
