# Deno and Bun install through Homebrew

### Bug fixes

- **Installing Deno or Bun ignored the Homebrew you already have.** v1.17.0 taught Hypergate to rank a present system package manager above everything else, and it does. What it could not do is rank a route the catalog never listed, and these two tools carried only their vendor's `curl … | bash` script. So on a Mac with Homebrew sitting right there, Install piped a shell script into your home directory instead, and the tool that arrived had no upgrade or uninstall Hypergate could offer afterwards.

  Both now carry the Homebrew route their own docs publish: `brew install deno`, and for Bun the tap Oven documents, `brew install oven-sh/bun/bun`. Uninstall and Repair follow from it, so a Bun installed this way is removed by the tap path it came from rather than a formula that merely shares its name. The vendor script stays as the runner-up for a machine without Homebrew, and nothing changes on Windows or on a Mac that has no `brew`.

- **Manage no longer offers to uninstall a tool with the wrong package manager.** Giving Bun a Homebrew route had a side effect: for a Bun already installed by its own script into `~/.bun/bin`, the Manage panel started defaulting to Homebrew and offering a `brew uninstall` that would never have found it. Where the installed path names no package manager the tool has a route for, Manage now prefers re-running the vendor's own installer, which is how those copies upgrade, and offers no uninstall. A tool you did install through Homebrew is unaffected and still manages through Homebrew.

Wrangler, Vercel and the Playwright CLI are deliberately still npm-only. Homebrew does package the first two, but neither Cloudflare nor Vercel documents that route, and a curated route says what the vendor says rather than what a repackaging happens to offer.
