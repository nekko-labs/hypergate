# A broken remote server tells you what is wrong

One release for one thing: when a hosted MCP endpoint fails, Hypergate now says so in a sentence instead of pasting the endpoint's error page into the server row.

### Bug fixes

- **A failing remote server shows one readable line, not a wall of HTML.** Hosted endpoints answer their failures with a web page, and Hypergate used to display that entire page as the server's error, with the status code lost somewhere inside it. A server that returns HTTP 500 now reads: "HTTP 500: the endpoint answered with an HTML error page instead of MCP. The host is failing upstream, so there is nothing to fix in this config." The advice fits the status, so a 401 asks you to sign in again and a bad URL says to check it. The full response is still in the server's log panel if you want it.
- **A remote server that is down no longer asks you to sign in.** Whether a server needed authorizing was decided by looking for "401" anywhere in the error text, and an error page's own markup can contain that string for unrelated reasons. Hypergate now reads the actual HTTP status, so only a real 401 sends you to sign in.
