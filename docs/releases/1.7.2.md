# The credential vault, and the gate made of light

The first published build since 1.5.0: it carries the credential vault, the softened rotating gate mark, and the two Mac packaging fixes that kept 1.6.0, 1.7.0 and 1.7.1 from being released at all.

### Features

- **A Credentials section in the manager.** Store any API key or access token once; it goes into the OS keychain (Windows Credential Manager, macOS Keychain, Linux Secret Service), never into a config file. Every row shows a masked hint, where the key is used, and when it was last handed out — the value itself never comes back over the API.
- **Guides for getting each key.** GitHub, Fly.io, Vercel, Cloudflare, Supabase, npm, Anthropic and OpenAI entries link the provider's own create-token page or command, and know which env var the key belongs in. `hypergate cred guide` prints the same instructions in the terminal.
- **Keys are gated per agent, deny-by-default.** A connected agent gets no credentials until you flip one on for it. An allowed agent fetches a key itself through the gateway's new `hypergate__credential_env` tool instead of stopping to ask you to sign in; every fetch and every refusal shows up in Analytics under the agent's name.
- **`hypergate run` re-authenticates CLIs without prompts.** `hypergate run -- flyctl deploy` injects the stored keys into the command's environment (never its argv, never printed). `--agent` narrows the injection to one agent's allow-list.
- **Managed servers reference keys instead of storing them.** A server config carries `credentialRefs` (env var → credential id) and the daemon resolves the value from the keychain at launch, so adding a catalog server that requires a token no longer writes it into `servers.json`.
- **Rolling is one step.** Replace a key's value and every running server that references it restarts onto the new value. Deleting a credential removes the value, every agent grant, and every server reference together.
- **`hypergate cred` in the terminal.** `cred ls`, `cred set fly` (value from stdin, guide-aware), `cred rm`, `cred guide`, `cred allow`/`deny`.
- **The gate mark is made of light, and it turns.** The ring's edges fade into the space around them the way the gate on hypergate.app does — in the tray icon, the app window icon, the manager's top bar and the favicon — and the startup window and top-bar mark rotate slowly while Hypergate is running.

### Bug fixes

- **The grey line across the top of the icon is gone.** A pale highlight sat over the ring and read as a scratch at icon sizes; the brand gradient carries the highlight now.
- **The macOS icon follows the softened mark.** The packaging-only copy of the mark that Mac installers are built from still drew the old hard-edged ring, and it stopped the Mac build of both 1.6.0 and 1.7.0 outright — which is why neither shipped. It now renders the same feathered ring, verified pixel-for-pixel against the renderer the app itself uses.
- **The Mac disk image no longer loses a race with Finder.** Building the installer failed outright if Finder still held the image's volume when the layout was finished (`hdiutil: couldn't unmount "disk9" - Resource busy`); the build now waits for the volume to be released instead of giving up.
- **A failed start no longer spins forever.** When Hypergate cannot bring the daemon up, the startup window's gate stops instead of implying it is still waiting.

### Security

- Vault mutations require the master gateway token plus a same-origin request, like shutdown and the OAuth app setup, so no page you happen to visit can create, roll, delete, or grant a key.
- The `hypergate` server id is now reserved for the gateway's own tools, so a managed server can never shadow `hypergate__credential_env`.

### Performance improvements

- **The new motion costs nothing to speak of.** It runs entirely on the GPU compositor — no repaints, no 3D context, and no animation at all for anyone whose system asks for reduced motion.
