# Hypergate can find itself on an npm install

One bug, found by updating a real machine instead of a test layout, with three separate symptoms.

### Bug fixes

- **Updating from an npm install failed** with "the hypergate shell binary is not available to run the update". Hypergate looked for its own executable on your PATH, and a global npm install never puts it there. So one-click updates could not run on the one channel that offers them.
- **Same cause, wider blast radius.** Everything that needed that executable was failing quietly, which meant that on every npm install your server sign-ins and gateway token were written as files in your home folder instead of your operating system's keychain, and Run on startup fell back to a less reliable route. One fix restores all three.
