# Permissions by tool, guards, and your team

Everything hypergate.app promises about permissions, guards and teams now ships.

### Features

- **Permissions by tool, and a read-only mode.** Open an agent and the new Tools block lists every tool of every server it can reach. Block one with a click, or switch on read-only so the agent only sees tools their server declares read-only. Blocked tools are hidden from the agent and refused if it calls them anyway.
- **Vault keys can't leave through a tool call.** A call whose arguments contain a key from your vault is refused before it reaches the server, and any vault key that comes back in a result is redacted. Both are recorded in the audit log, without the key.
- **Insights.** Analytics > Security now shows what needs a look: blocked keys, an agent repeatedly calling tools it isn't allowed, first-time use of tools that can change things, bursts of calls, error spikes and new callers.
- **Ask your own agent.** Agents with access to every server get `hypergate__audit_review`, a digest of the audit log, so the agent you already run can tell you what matters. Copy the prompt from Analytics. Hypergate itself runs no AI.
- **Team access (opt-in).** Invite people under Servers > People: each gets their own token, scoped by server and tool like an agent. Turn on Team access in Settings and pick an address (Tailscale is suggested first). That address serves only the gateway, and only to people's tokens. Your agents' tokens, the vault and the manager stay on your machine.
- **A header built around what you do.** The Servers view now opens with Connect an agent, Add a server and Invite a person, beside your endpoint and token.

### Bug fixes

- Settings panels no longer cut off their last row (Start minimized was hidden at ordinary window sizes).
