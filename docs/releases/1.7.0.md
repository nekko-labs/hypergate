# The credential vault

Hypergate now holds the keys — API keys and access tokens for the CLIs and MCP servers your agents use — in the OS keychain, gated per agent, with the provider's own instructions for getting and rolling each one.

### Features

- **A Credentials section in the manager.** Store any API key or access token once; it goes into the OS keychain (Windows Credential Manager, macOS Keychain, Linux Secret Service), never into a config file. Every row shows a masked hint, where the key is used, and when it was last handed out — the value itself never comes back over the API.
- **Guides for getting each key.** GitHub, Fly.io, Vercel, Cloudflare, Supabase, npm, Anthropic and OpenAI entries link the provider's own create-token page or command, and know which env var the key belongs in. `hypergate cred guide` prints the same instructions in the terminal.
- **Keys are gated per agent, deny-by-default.** A connected agent gets no credentials until you flip one on for it — the mirror of the per-server switches. An allowed agent fetches a key itself through the gateway's new `hypergate__credential_env` tool instead of stopping to ask you to sign in; every fetch and every refusal shows up in Analytics under the agent's name.
- **`hypergate run` re-authenticates CLIs without prompts.** `hypergate run -- flyctl deploy` injects the stored keys into the command's environment (never its argv, never printed), so an expired login stops being a conversation with the user. `--agent` narrows the injection to one agent's allow-list.
- **Managed servers reference keys instead of storing them.** A server config carries `credentialRefs` (env var → credential id); the daemon resolves the value from the keychain at launch. Adding a catalog server that requires a token now stores the token in the vault instead of writing it into `servers.json`.
- **Rolling is one step.** Replace a key's value and every running server that references it restarts onto the new value; agents pick it up on their next fetch. Deleting a credential removes the value, every agent grant, and every server reference together.
- **`hypergate cred` in the terminal.** `cred ls`, `cred set fly` (value from stdin, guide-aware), `cred rm`, `cred guide`, `cred allow`/`deny` — all against the same daemon API the manager uses.

### Security

- Vault mutations require the master gateway token plus a same-origin request, like shutdown and the OAuth app setup, so no page you happen to visit can create, roll, delete, or grant a key.
- The `hypergate` server id is now reserved for the gateway's own tools, so a managed server can never shadow `hypergate__credential_env`.
- Test daemons can set `HYPERGATE_NO_KEYCHAIN=1` to keep scratch secrets in their own temp directory instead of the real keychain.
