# The credential vault ships, and Mac releases build again

This release carries everything since v1.5.0: v1.6.0 and v1.7.0 were tagged but never published, because the macOS build job had been failing since the v1.6.0 icon redesign. Their release notes ([1.6.0](1.6.0.md), [1.7.0](1.7.0.md)) describe the bulk of what lands here.

### Highlights carried from v1.7.0 — the credential vault

- **Store API keys and access tokens in the OS keychain**, never in config files, with masked metadata and no reveal endpoint.
- **Gate keys per agent, deny-by-default**, fetched by allowed agents through the gateway's new `hypergate__credential_env` tool — every fetch and refusal visible in Analytics.
- **`hypergate run -- <cmd>` re-authenticates CLIs without prompts**, and `hypergate cred` manages the vault from the terminal with vendor-true guides for getting each key.
- **Managed servers reference keys** (`credentialRefs`) resolved at launch; rolling a key restarts the servers that use it, deleting one cleans up every grant and reference.

### Highlights carried from v1.6.0

- The Hypergate mark glows instead of being drawn — feathered edges, no hard outline — and turns slowly in the startup window and the manager top bar, at compositor-only cost.

### Bug fixes

- **macOS release builds work again.** The packaging-only JavaScript copy of the icon renderer (`scripts/gen-icns.mjs`) still drew the pre-v1.6.0 mark, and its deliberate drift guard failed the build the moment `icon.rs` changed — which is exactly what it is for. The renderer now draws the v1.6.0 hollow gate (feathered annulus, ice bloom on the crests instead of the white hot arc, the halo blended under the ring's outer edge), verified against the same pixel expectations `icon.rs`'s own tests assert, and the guard now pins the current geometry's literals.
