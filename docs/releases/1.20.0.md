# The stdio gateway finishes connecting before it answers

### Bug fixes

- **`hypergated --stdio` could answer a request before it had finished attaching.** It connected its stdio channel first and only then looked up the upstream tool list and reported which daemon it had attached to. A harness that acted on the first response and exited immediately could miss that report entirely.

  Everything that can fail, and everything worth logging, now happens before the stdio channel starts serving.

- **A failure at exactly the wrong moment could leave two servers on one channel.** If the tool lookup failed after the stdio channel was already connected, the proxy reported that it had not attached, and the fallback path connected a second stdio server to the same input. Both would have been reading the same stream. The reordering above makes that unreachable, since every failure is now handled before anything is connected.
