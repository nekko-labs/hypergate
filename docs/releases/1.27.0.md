# Credential lockdown

Keep API keys out of agents' hands, whichever model or harness runs them, and find the logins tools keep outside the vault.

### Features

- **Credential lockdown.** One switch (`hypergate lockdown on`, or the toggle in Credentials) and no agent ever receives a key's value again. Keys reach a command only through `hypergate run`, only for programs the key is bound to (`GITHUB_TOKEN` to `gh` and `git`, for example). Shells, interpreters and commands that print tokens (`gh auth token`, `fly auth token`, ...) are refused. Anything that widens access, and turning lockdown off, asks Touch ID, Windows Hello or polkit first.
- **Ambient logins.** Hypergate finds the keys tools keep for themselves: GitHub CLI, Fly.io, Vercel, Supabase, npm and Git logins, and model-provider keys like `OPENAI_API_KEY`, `OPENROUTER_API_KEY` and `GEMINI_API_KEY` exported from your shell startup files or stored by Codex, Gemini CLI and aider. **Move into vault** imports one and removes it at the source, after a backup. `hypergate cred sweep` does the same in the terminal.
- **Watch and alert.** Hypergate notices new logins and newly installed CLIs, tells you with a desktop notification, and can tell your team through a Slack-compatible webhook (off until you set a URL; it never sends a key or part of one). Optional auto-quarantine moves new logins into the vault as they appear.
- **Agent instructions.** Hypergate can add a short, clearly marked block to each agent's global instruction file (Claude Code, Codex, Gemini CLI, OpenCode, Devin Desktop) asking it to run keys through Hypergate and request access instead of working around it. Offered, never written silently; `hypergate instructions remove` takes it out. Claude Code plugin users get the same rules as a skill.

### Changes

- Lockdown is a strong default, not a sandbox. An agent running as your OS user can still read a stored key with `hypergate secret get`, borrow another connected agent's grants, or leak a key through a bound program that runs arbitrary code. An OS sandbox around agents is planned.
