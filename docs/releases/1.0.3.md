# The Mac app starts

A patch release for one bug: on macOS, Hypergate never got past "Starting Hypergate…".

### Bug fixes

- **The Mac app starts.** Every signed macOS build shipped a daemon that could not launch at all — its signature was missing the entitlements Node needs to run — so the app sat on "Starting Hypergate…" forever. Update to this version; an already-installed copy stays broken until it is replaced.
- **A Mac install is now a drag, not a wizard.** macOS ships as a `.dmg`: open it, drag Hypergate to Applications. The `hypergate` command is created for you on first launch, without an admin prompt, and `Hypergate.app/Contents/Resources/uninstall.sh` reverses everything except your `~/.hypergate` data.
- **Waiting for the daemon is no longer a dead end.** The startup screen says how long it has been waiting instead of sitting silent, gives up on the visible wait after 30 seconds rather than 90, and still opens the manager by itself if the daemon comes up later — where it used to leave you on an error page for the rest of the session.
- **A startup failure says why.** The reason the daemon could not be reached now goes to `~/.hypergate/hypergate.log`, along with how long startup took, instead of being discarded.
